1Foundations of Routing

Before we dissect algorithms and protocols, we must understand the fundamental question that routing answers: how does a packet find its way through a vast, ever-changing labyrinth of links and routers? This chapter establishes the conceptual vocabulary and architectural distinctions that every university examination expects you to wield with precision.

What is Routing?

Imagine you are in Delhi and wish to send a letter to a friend in Chennai. You do not personally know every road, railway junction, and postal hub between the two cities. Instead, you hand the letter to your local post office, trusting that each subsequent sorting facility will read the destination address and forward the letter along the most appropriate outgoing link. Routing in computer networks operates on precisely this principle, though at speeds measured in nanoseconds and scales spanning the entire planet.

Formally, routing is the process of selecting paths in a network along which to send data traffic. It is a control-plane function: it determines which path a packet should take, whereas the data-plane function of forwarding actually moves the packet from an input port to the correct output port based on a locally-stored forwarding table. The distinction is subtle but examination-critical. Routing is the global, often slow, algorithmic computation of paths; forwarding is the local, blisteringly-fast lookup operation performed millions of times per second.

Formal Definition

Given a graph G = (N, E) where N is the set of routers and E is the set of links, a routing algorithm computes a least-cost path from a source node s ∈ N to every destination d ∈ N, where the cost of a path (n1, n2, …, nk) is the sum ∑ c(ni, ni+1) of individual link costs.

The cost c(x, y) associated with a link is an administrative choice. It may reflect physical distance, monetary cost, link capacity, current congestion, or simply a unit value for every hop. In university examinations, unless stated otherwise, assume costs are static, non-negative integers assigned to undirected edges.

Static versus Dynamic Routing

Static routing resembles a pre-printed roadmap. A network administrator manually configures each router's forwarding table. The paths never change unless a human intervenes. The advantage is simplicity and predictability: no protocol overhead, no convergence delays, no unexpected route changes during examinations. The disadvantage is fragility. If a link fails, traffic continues to be black-holed toward the broken path until someone manually updates the tables. Static routing is viable only for trivial topologies—perhaps a three-router campus laboratory or a stub network with a single exit point.

Dynamic routing, by contrast, endows the network with autonomic reflexes. Routers run algorithms that periodically discover topology, exchange reachability information, and recalculate optimal paths. When a link fails, the algorithm detects the change (through missed hello packets or cost updates) and reroutes traffic around the failure. The price for this resilience is complexity: protocol overhead, potential routing loops during convergence, and the infamous oscillations and count-to-infinity problems we shall examine in later chapters. In modern networks, dynamic routing is the default; static routes are reserved for special cases such as default routes or policy-driven exceptions.

Global versus Decentralized Routing

This classification concerns what information each router possesses before running the algorithm. In global (or link-state) routing, every router maintains a complete map of the entire network topology and all link costs. This global knowledge is typically achieved through a link-state broadcast: each router floods the network with a packet describing its local links, and every other router collects these packets to build an identical copy of the complete graph. Once the map is assembled, each router independently runs a shortest-path algorithm—almost always Dijkstra's—to compute its own forwarding table. No router needs to trust another's path computation; the computation is local, deterministic, and based on globally consistent data.

In decentralized (or distance-vector) routing, no router knows the full map. Each router begins with knowledge only of its directly attached neighbors and the costs to reach them. It then engages in an iterative conversation: routers exchange their distance vectors—arrays of estimated least costs to every destination—and each router updates its own estimates using the Bellman-Ford equation. The process repeats until the estimates stabilize, a state called convergence. The algorithm is beautiful in its distributed simplicity, yet treacherous in its susceptibility to routing loops and slow propagation of bad news.

Analogy: Global routing is like every driver in a city possessing an identical, perfectly accurate paper map and independently plotting the fastest route. Decentralized routing is like asking directions at every intersection: "How far is the railway station?" Each passerby gives an estimate based on what they were told by the next person down the road. Eventually the estimates settle, but a broken bridge at one end of the city may take a while to register at the other end.

Broadcast, Multicast, and Unicast Routing

Unicast is the default mode: one source, one destination. The routing algorithm finds a single path from sender to receiver. Broadcast demands that a packet reach every node in the network. The naïve approach—sending a separate unicast copy to each destination—squanders bandwidth and router resources. A more intelligent approach uses source-based broadcast: the source transmits a single copy, and each router replicates it onto all outgoing links except the one on which it arrived. This generates a spanning tree rooted at the source. Even better is network-supported broadcast, where routers collaboratively construct a spanning tree (using protocols like the Spanning Tree Algorithm) and forward broadcast packets only along tree edges, eliminating redundant transmissions.

Multicast occupies the middle ground: one source to a subset of receivers who have explicitly joined a multicast group. The challenge is to deliver packets along a tree that reaches only the interested receivers. Protocols like IGMP (Internet Group Management Protocol) allow hosts to signal their group membership to local routers, while multicast routing protocols (such as DVMRP or PIM) build either source-based trees or shared trees rooted at a rendezvous point. For examination purposes, remember the hierarchy: unicast is point-to-point, broadcast is point-to-all, and multicast is point-to-group.

Exam Writing Tip: When asked to compare broadcast and multicast, emphasize that broadcast is a special case of multicast where the group includes every node, but the critical difference lies in efficiency—multicast constructs a delivery tree that prunes branches leading to uninterested subnets, whereas broadcast floods all links.

Hierarchical Routing and Mobile Hosts

As networks grow to thousands of routers, flat routing becomes computationally and administratively impossible. Hierarchical routing partitions the network into autonomous systems (ASes)—regions under a single administrative authority. Routers within an AS run an intra-AS (interior gateway) protocol such as OSPF or RIP. Routers that sit on the boundary of an AS, called gateway routers, run an inter-AS (exterior gateway) protocol—in practice, always BGP—to exchange reachability information with other ASes. This hierarchy reduces routing table size, limits protocol overhead, and respects administrative autonomy: a university campus need not reveal its internal topology to its upstream ISP.

Mobile host routing introduces the problem of a host whose point of attachment to the network changes. The classic solution, exemplified by Mobile IP, employs two addresses: a permanent home address and a temporary care-of address assigned at the foreign network. A home agent on the home network intercepts packets destined for the mobile host and tunnels them to the care-of address. A foreign agent (or the mobile host itself, in IPv6) decapsulates the packets and delivers them. When the mobile host replies, it may send packets directly to the correspondent or route them back through the home agent, depending on the specific protocol variant.

2The Link-State (LS) Algorithm

The link-state algorithm transformed the ARPANET in 1979, replacing the fragile distance-vector scheme with a method that offered faster convergence and greater stability. At its heart lies Dijkstra's shortest-path algorithm, a greedy procedure that builds a tree of least-cost paths one node at a time. This chapter explains not merely how Dijkstra works, but why it works, and walks through the canonical seven-node examination problem step by step.

Dijkstra's Shortest-Path Algorithm: Mechanics

Edsger W. Dijkstra published his algorithm in 1959, though legend holds that he conceived it in twenty minutes while resting on a terrace in Amsterdam. The algorithm solves the single-source shortest-path problem for a graph with non-negative edge weights—a condition that holds in virtually all routing contexts, since link costs are typically positive measures of distance, delay, or congestion.

Each router executing the link-state algorithm maintains two data structures. First, a set N' containing all nodes whose least-cost path from the source has been definitively determined. Second, for every node v not yet in N', a value D(v) representing the current best estimate of the least cost from the source to v, and a predecessor p(v) recording the previous node along that estimated path.

Dijkstra's Algorithm (Pseudocode)
Initialization:
  N' = {u}                          // u is the source node
  for all nodes v:
    if v is a neighbor of u:
      D(v) = c(u,v)
      p(v) = u
    else:
      D(v) = ∞
      p(v) = undefined

Loop:
  find w not in N' such that D(w) is minimum
  add w to N'
  for each neighbor v of w not in N':
    if D(w) + c(w,v) < D(v):
      D(v) = D(w) + c(w,v)
      p(v) = w
  until all nodes are in N'

The algorithm's correctness rests on a crucial greedy-choice property: when we select the node w with the minimum D(w) outside N', we are guaranteed that D(w) equals the true least cost from the source to w. Why? Because all edge costs are non-negative, any alternative path to w would have to pass through some node x not yet in N'. But D(x) ≥ D(w) by our selection criterion, and the additional edges from x to w can only increase the cost further. Thus no unvisited node can offer a cheaper path.

The time complexity is O(n2) for a naive implementation with n nodes, since each iteration scans all unvisited nodes to find the minimum. With a min-heap (priority queue), this improves to O((n + e) log n), where e is the number of edges. For dense networks typical of link-state protocols, the heap version is preferred.

Step 0 (Initialization): The source x is placed in N'. For each neighbor, we record the direct link cost: D(v) = 3 via x, D(w) = 6 via x, D(y) = 6 via x, and D(z) = 8 via x. Nodes t and u are not neighbors, so their estimates remain infinity.

For t: the path x → v → t costs 3 + 4 = 7, so D(t) becomes 7 with predecessor v. For u: the path x → v → u costs 3 + 3 = 6, so D(u) becomes 6 with predecessor v. For w: x → v → w costs 3 + 4 = 7, which exceeds the current D(w) = 6, so we do not update. For y: x → v → y costs 3 + 8 = 11, exceeding D(y) = 6; no update.

Step 2 (Add u): The minimum unvisited estimate is now D(u) = 6 (tied with w and y; we break ties arbitrarily). Finalizing u, we examine its neighbors. u → t has cost 2, so the path x → v → u → t would cost 6 + 2 = 8, which exceeds the current D(t) = 7. u → w has cost 3, giving x → v → u → w at cost 9, exceeding D(w) = 6. No updates occur.

Step 3 (Add w): With D(w) = 6, we finalize w. Its neighbors are x (already in N'), v (in N'), and u (now in N'). No unvisited neighbors remain, so no updates.

Step 4 (Add y): D(y) = 6 is next. Examining y's unvisited neighbors: z would cost 6 + 12 = 18 (exceeds 8); t would cost 6 + 7 = 13 (exceeds 7). No updates.

Step 5 (Add t): D(t) = 7. Its only unvisited neighbor is z (via t → z? No such link exists in the topology). No updates.

Step 6 (Add z): D(z) = 8. All nodes are now in N'. The algorithm terminates.

Link-State versus Distance-Vector: A Critical Comparison

University examinations relish comparison questions. A high-scoring answer must move beyond bullet points to analyze the architectural trade-offs. Link-state algorithms converge relatively quickly—O(n2) computation after O(nE) messages—and because each router computes its own table independently, a malfunctioning router can only corrupt its own forwarding information, not poison the entire network. However, link-state protocols broadcast substantial information (every router's local links) across the whole network, consuming bandwidth. They are also vulnerable to oscillations when link costs depend on traffic volume: routers may synchronously shift traffic to the least-cost path, overloading it, then shift back, creating perpetual oscillation.

Distance-vector algorithms are message-frugal, exchanging vectors only with immediate neighbors. But convergence time is unpredictable, and the count-to-infinity problem can cause routing loops that persist for many update cycles. Worse, a single router advertising incorrect path costs can propagate that error through the entire network, because each router's table becomes input for its neighbors' computations.

3The Distance-Vector (DV) Algorithm

Where link-state algorithms demand omniscience, distance-vector algorithms embrace humility. Each router knows only its neighbors and trusts them to report their own best estimates. This recursive trust, formalized by the Bellman-Ford equation, creates an elegant distributed system—one that is mathematically beautiful but practically treacherous.

The Bellman-Ford Equation

Let dx(y) denote the true least cost from node x to destination y. The Bellman-Ford equation states that this cost equals the minimum, over all neighbors v of x, of the sum of the direct link cost c(x, v) plus the neighbor's least cost to the destination:

dx(y) = minv { c(x, v) + dv(y) }

This equation is a statement of dynamic programming optimality. If the shortest path from x to y passes through neighbor v, then the total cost must be the cost to reach v plus the cost of the shortest path from v to y. Since we do not know a priori which neighbor lies on the optimal path, we minimize over all possibilities.

In practice, each router x maintains an estimate Dx(y) rather than the true dx(y). It also stores the distance vectors received from each neighbor. Whenever a new vector arrives, x recomputes its own estimates using the equation above. If any estimate changes, x transmits its updated vector to all neighbors, triggering further updates. The process continues until no estimates change—this is convergence.

The Count-to-Infinity Problem

Distance-vector routing suffers from a pathological failure mode that link-state routing avoids entirely. Suppose in a linear topology A–B–C, the link from A to its destination fails. B had been routing to A through the direct link (cost 1). When A fails, B should set its cost to A as infinity. But before B can announce this, C may send its vector to B claiming it can reach A with cost 2. B, not knowing that C's path to A runs through B itself, updates its cost to A as 3 (via C). B then announces this to C, which updates its cost to 4. The costs increment indefinitely—hence counting to infinity—until they exceed some maximum (in RIP, 16 hops), at which point the route is finally declared unreachable.

Figure 3.2 — The count-to-infinity problem in a three-node chain after link failure.

The root cause is mutual deception: B believes C has an independent path to A, and C believes B has an independent path to A, when in fact each is relying on the other. The Bellman-Ford equation has no mechanism to detect that a neighbor's advertised path contains a loop through oneself.

Mitigations: Split Horizon and Poisoned Reverse

Split horizon is a simple rule: never advertise a route back to the neighbor from whom you learned it. If B's best path to A is through C, then when B sends its vector to C, it omits the entry for A. This prevents the two-node loop in our example, because C never sees B's (now incorrect) route to A. However, split horizon fails to prevent larger loops involving three or more nodes.

Poisoned reverse strengthens this idea: instead of omitting the route, explicitly advertise it with cost infinity. If B routes to A through C, B tells C that its distance to A is ∞. This immediately dissuades C from using B as a next hop to A, rather than waiting for a timeout. In practice, RIP implements split horizon with poisoned reverse, and sets infinity to 16 hops—an intentionally small value that limits both network diameter and convergence time after a failure.

Memory Anchor

"Split Horizon = Silent Treatment; Poisoned Reverse = Honest Rejection." In split horizon, you simply don't tell your ex about your plans. In poisoned reverse, you explicitly say, "I am never going there," so they don't get false hope.

4Intra-AS Routing: OSPF & RIP

An autonomous system is an island of administrative sovereignty in the archipelago of the Internet. Within each island, routers must agree on a common language to describe topology and compute paths. RIP and OSPF are the two historic contenders for this role—one simple but limited, the other sophisticated and scalable.

RIP: Routing Information Protocol

RIP is the elder statesman of interior gateway protocols, standardized in 1988 and derived directly from the Xerox PUP protocol. It is a pure distance-vector protocol that uses hop count as its metric: every link has cost 1, and the path cost is simply the number of routers traversed. RIP permits a maximum of 15 hops; 16 is infinity. This small infinity value is not an arbitrary choice—it is a deliberate defense against count-to-infinity, ensuring that loops self-destruct quickly.

RIP routers broadcast their entire routing table to all neighbors every 30 seconds. When a router receives an update, it applies the Bellman-Ford equation. If a route is not refreshed within 180 seconds, it is marked unreachable (cost 16) and eventually removed. RIP implements split horizon with poisoned reverse and supports triggered updates for rapid convergence after failures.

RIP Limitations
  • Small diameter: Networks exceeding 15 hops are unreachable.
  • Slow convergence: Count-to-infinity remains possible despite mitigations.
  • Metric rigidity: Hop count ignores bandwidth, delay, and congestion.
  • Periodic flooding: Full table broadcasts every 30 seconds waste bandwidth.

OSPF: Open Shortest Path First

OSPF, standardized in 1989, represents the link-state paradigm in the Internet's interior. It abandons the distance-vector approach entirely in favor of Dijkstra's algorithm running over a topology database that every router constructs through link-state flooding. OSPF uses IP protocol 89 and operates directly above IP, unlike RIP which rides on UDP port 520.

The protocol organizes an AS into areas, a hierarchical refinement that prevents the link-state database from growing unwieldy. Area 0, the backbone, sits at the center; all other areas must attach to it via area border routers (ABRs). Within an area, every router floods link-state advertisements (LSAs) describing its local links. There are several LSA types: Type 1 (router LSAs) describe router links; Type 2 (network LSAs) describe multi-access networks; Type 3 (summary LSAs) propagate inter-area routes from ABRs; and Type 5 (external LSAs) carry routes redistributed from other ASes via autonomous system boundary routers (ASBRs).

On broadcast networks such as Ethernet, OSPF elects a Designated Router (DR) and a Backup Designated Router (BDR). Rather than every router forming adjacencies with every other router (an O(n2) explosion), all routers establish adjacency only with the DR and BDR. The DR collects and distributes LSAs on behalf of the segment, dramatically reducing protocol overhead.

OSPF's cost metric is configurable, typically calculated as cost = reference_bandwidth / link_bandwidth. This allows OSPF to prefer high-capacity links over low-capacity ones, a flexibility RIP entirely lacks. OSPF also supports authentication, multiple equal-cost paths (ECMP), and graceful restart mechanisms.

Viva Voce Favorite: "Why does OSPF use areas?" The correct answer is not merely "to reduce overhead." Areas bound the link-state database to a manageable size, while ABRs summarize reachability between areas, preserving scalability without sacrificing correctness.

5Inter-AS Routing: BGP

If intra-AS protocols are the dialects spoken within sovereign nations, BGP is the diplomatic language of the Internet. It does not merely find shortest paths; it negotiates policy, enforces commercial contracts, and prevents the anarchic flooding of routing information across administrative boundaries. Understanding BGP is essential for any student aspiring to explain how the Internet actually functions.

The Path-Vector Approach and Policy Routing

BGP (Border Gateway Protocol) is a path-vector protocol. Unlike distance-vector protocols, which advertise only costs, BGP routers advertise the full AS-PATH—the complete sequence of autonomous systems that a route traverses. This seemingly simple addition solves the count-to-infinity problem at the inter-AS level: if a router receives a path containing its own AS number, it immediately discards the route as a loop.

More importantly, the AS-PATH enables policy-based routing. An ISP may refuse to advertise a route to a competitor, prefer paths through cheaper transit providers, or avoid routes traversing geopolitically sensitive regions. These policies are expressed as import and export filters configured on BGP sessions. No intra-AS protocol offers this granularity, because within an AS all routers share a common administrative goal; between ASes, goals diverge.

BGP operates over TCP port 179, ensuring reliable delivery of routing updates. This contrasts sharply with RIP (UDP) and OSPF (directly over IP). The TCP connection is maintained between BGP peers (also called speakers). When the TCP session is established, peers exchange their entire routing tables; subsequently, only incremental updates are sent.

BGP Attributes and Route Selection

A BGP route is not merely a destination prefix; it is a rich data structure called a Network Layer Reachability Information (NLRI) entry adorned with path attributes. Examiners frequently test knowledge of the following attributes:

AttributeTypePurpose
AS-PATHWell-known mandatoryLists ASes traversed; used for loop detection and path length comparison
NEXT-HOPWell-known mandatoryIP address of the next-hop router toward the destination
ORIGINWell-known mandatoryIndicates how the route was injected (IGP, EGP, or incomplete)
LOCAL-PREFWell-known discretionaryPreference value for internal AS path selection; higher is preferred
MEDOptional non-transitiveMulti-Exit Discriminator; suggests preferred entry point from neighboring AS

When a BGP router receives multiple routes to the same prefix, it applies a deterministic route selection algorithm:

  1. Prefer the route with the highest LOCAL-PREF (local policy).
  2. If tied, prefer the route with the shortest AS-PATH.
  3. If tied, prefer the route with the lowest ORIGIN type (IGP < EGP < Incomplete).
  4. If tied, prefer the route with the lowest MED.
  5. If tied, prefer eBGP over iBGP routes.
  6. If tied, prefer the route with the lowest IGP cost to the NEXT-HOP.
  7. If still tied, prefer the route from the router with the lowest BGP Router ID.

This hierarchy is worth memorizing. Examiners love to present scenarios where two routes differ in multiple attributes and ask which will be selected.

eBGP versus iBGP

eBGP (external BGP) runs between routers in different autonomous systems, typically directly connected at peering points. It is the protocol of the Internet's edge, where ISPs exchange reachability information. eBGP sessions often enforce strict prefix limits and route filters to prevent accidental table explosions.

iBGP (internal BGP) runs between routers within the same AS. Its purpose is to distribute external routes learned via eBGP to all internal routers. Here lies a subtlety: iBGP does not modify the AS-PATH, because the path must remain unchanged when advertised to external peers. Consequently, iBGP requires a full mesh of sessions—or the use of route reflectors and confederations—to ensure every internal router learns external routes. Without this mesh, a router receiving an iBGP route would not re-advertise it to other iBGP peers, creating black holes.

Analogy: eBGP is like two countries signing a trade agreement at their border. iBGP is like the customs office within one country informing every port and airport about the new agreement so that goods can be routed internally to the correct exit point.

BGP vs. IGPs: Critical Distinctions
  • Scale: BGP handles ~900,000 IPv4 prefixes globally; OSPF and RIP cannot.
  • Policy: BGP filters routes based on business relationships; IGPs optimize for shortest path.
  • Loop prevention: BGP uses AS-PATH; OSPF uses shortest-path tree; RIP uses hop-count limit.
  • Transport: BGP uses reliable TCP; OSPF and RIP use best-effort IP/UDP.
  • Convergence: BGP is intentionally slow and conservative; IGPs converge rapidly.

6IPv4 Addressing, Subnetting & CIDR

IP addressing is the postal code system of the Internet. Yet unlike postal codes, which are purely hierarchical, IP addresses must balance geographic aggregation with the practical need for flexible allocation. This chapter unpacks the 32-bit IPv4 address, the art of subnetting, the revolutionary simplicity of CIDR, and the gritty reality of packet fragmentation.

IPv4 Header and Addressing Architecture

An IPv4 address is 32 bits long, conventionally written in dotted-decimal notation as four octets (e.g., 192.168.1.1). The original classful addressing scheme partitioned the address space into five classes:

ClassLeading BitsNetwork BitsHost BitsDefault MaskAddress Range
A0824255.0.0.01.0.0.0 – 126.255.255.255
B101616255.255.0.0128.0.0.0 – 191.255.255.255
C110248255.255.255.0192.0.0.0 – 223.255.255.255
D1110Multicast (no network/host split)—224.0.0.0 – 239.255.255.255
E1111Reserved for experimental use—240.0.0.0 – 255.255.255.255

Classful addressing proved wasteful. A Class A network could host 16 million devices, yet most organizations needed only thousands. A Class C network provided merely 254 hosts, insufficient for mid-sized enterprises. The rigid boundaries between classes created a crisis of address exhaustion long before the total pool was depleted.

Subnetting Mechanics

Subnetting borrows bits from the host portion of an IP address to create a subnet identifier. This allows a single network address to be partitioned into multiple smaller broadcast domains. The boundary between network, subnet, and host portions is defined by the subnet mask—a 32-bit value with contiguous 1s followed by contiguous 0s. When a bitwise AND is performed between an IP address and its subnet mask, the result is the network (or subnet) address.

For example, consider the Class B address 172.16.0.0 with default mask 255.255.0.0. If we borrow 8 bits from the host portion, the subnet mask becomes 255.255.255.0 (/24 in CIDR notation). We now have 256 possible subnets (28), each supporting 254 hosts (28 − 2, subtracting the all-zeros and all-ones addresses). The first subnet is 172.16.0.0/24, the second is 172.16.1.0/24, and so forth.

HOSTS PER SUBNET = 2(host bits) − 2
SUBNETS = 2(borrowed bits)

The subtraction of 2 accounts for the network address (all host bits zero) and the broadcast address (all host bits one). These addresses cannot be assigned to interfaces. In examinations, forgetting this subtraction is the most common arithmetic error.

CIDR and VLSM

Classless Inter-Domain Routing (CIDR), introduced in 1993, abolished the rigid class boundaries. An address is now written as a.b.c.d/n, where n indicates the number of leading bits in the network prefix. This enables supernetting (route aggregation): contiguous Class C networks can be merged into a single larger prefix. For instance, 192.168.0.0/24 through 192.168.7.0/24 aggregate to 192.168.0.0/21, reducing routing table entries from eight to one.

Variable Length Subnet Masking (VLSM) extends this flexibility by allowing different subnets within the same organization to use different prefix lengths. A point-to-point link between two routers needs only two host addresses, so a /30 subnet (2 usable hosts) suffices. A large department might need a /22 subnet (1022 hosts). VLSM allocates addresses precisely, minimizing waste. RIP v1 does not support VLSM because it does not transmit subnet masks; RIP v2, OSPF, and BGP all do.

Exam Technique: When asked to "design a subnetting scheme," always begin by calculating the number of subnets required and the maximum number of hosts per subnet. Choose the smallest prefix length (largest number of network bits) that satisfies both constraints. Show your work: borrowed bits, new mask, subnet addresses, usable host ranges, and broadcast addresses for at least three subnets.

Fragmentation and Reassembly

Different data links impose different maximum transmission units (MTUs). Ethernet typically allows 1500 bytes; PPPoE reduces this to 1492; some tunnels permit only 1280. When an IP datagram exceeds the outgoing link's MTU, the router must fragment it. Each fragment becomes an independent IP datagram with its own header. The Identification field is copied from the original to allow reassembly; the Fragment Offset indicates the fragment's position in the original datagram (measured in 8-byte blocks); and the More Fragments (MF) flag is set on all fragments except the last.

Reassembly occurs only at the destination host, never at intermediate routers. This design choice prevents routers from buffering partial packets and reduces state in the network core. If any fragment is lost, the entire original datagram is discarded after a reassembly timeout.

Solved Problem: MP3 File Fragmentation

Problem: Datagrams are limited to 1500 bytes (including header) between source Host A and destination Host B. Assuming a 20-byte IP header, how many datagrams are required to send an MP3 file of 4,000,000 bytes?

Solution:

Data per datagram = 1500 − 20 = 1480 bytes.

Number of datagrams = ceil(4,000,000 / 1480) = ceil(2702.7027) = 2703 datagrams.

The first 2702 datagrams carry 1480 bytes of data each:
2702 × 1480 = 3,998,960 bytes.

The final datagram carries the remainder:
4,000,000 − 3,998,960 = 1040 bytes of data.
Total size of last datagram = 1040 + 20 = 1060 bytes.

Verification: 2702 × 1480 + 1040 = 4,000,000 bytes. Correct.

7ICMP: The Internet Control Message Protocol

IP is a best-effort protocol: it delivers packets without guarantees, and when things go wrong, it offers no explanation. ICMP fills this silence. It is the Internet's diagnostic nervous system, reporting errors, testing reachability, and revealing the paths that packets traverse.

ICMP is not a transport-layer protocol; it is an integral part of IP, using IP protocol number 1. ICMP messages are encapsulated directly inside IP datagrams, though they are often described as residing "above" IP because they use IP's delivery service. Every ICMP message contains a type field, a code field, and a checksum. The type and code together identify the specific message purpose.

TypeCodeMeaningUsage

33Destination Unreachable (Port)No process listening on port
34Fragmentation Needed (DF set)Path MTU discovery

111Time Exceeded (reassembly timeout)Fragment loss
120Parameter ProblemMalformed IP header

Ping and Traceroute

Ping uses ICMP Echo Request (type 8, code 0) and Echo Reply (type 0, code 0) to test reachability. The source sends an Echo Request with an embedded timestamp and sequence number; the destination echoes the payload back. By measuring round-trip time and counting lost packets, ping assesses both connectivity and latency.

Traceroute exploits ICMP Time Exceeded messages to map the route to a destination. The source sends UDP packets (or ICMP Echo Requests, depending on implementation) to an unlikely destination port, starting with TTL = 1. The first router decrements TTL to 0, discards the packet, and returns an ICMP Time Exceeded message, revealing its identity. The source increments TTL to 2, exposing the second router, and continues until the destination is reached. The destination responds with an ICMP Port Unreachable (or Echo Reply), signaling termination.

Analogy: Ping is like shouting "Are you there?" across a canyon and listening for the echo. Traceroute is like sending a messenger with a candle that burns out after a fixed number of miles; each time the candle expires, the local village sends a letter back saying "Your messenger died here," revealing the path.

Common Student Confusion

Students often believe ICMP is a transport-layer protocol like TCP or UDP. It is not. ICMP has no port numbers, no sequence numbers (except within ping's payload), and no connection state. It is a control protocol for IP, carried directly inside IP datagrams. When asked to draw the protocol stack, place ICMP in the Network Layer box, not above UDP.

Most Commonly Confused Points

LS vs. DV: Which is more robust?+

Link-state is more robust to individual router failures because each router computes its own table. A faulty router can only advertise incorrect link costs, which other routers treat as local data points in their independent Dijkstra computations. In DV, a faulty router advertises incorrect path costs that neighbors incorporate directly into their own vectors, propagating error.

Why does BGP use TCP while OSPF does not?+

BGP exchanges large routing tables (hundreds of thousands of prefixes) over potentially unreliable inter-AS links. TCP provides reliable, ordered delivery and flow control, preventing session resets due to dropped updates. OSPF runs within an AS over relatively stable links and uses its own reliable flooding mechanism (acknowledged LSAs), making TCP overhead unnecessary.

Why must iBGP be fully meshed (or use route reflectors)?+

BGP's loop-prevention rule states that a router does not advertise an iBGP-learned route to another iBGP peer. Without a full mesh, a router learning an external route via one iBGP peer could never share it with another internal peer, creating reachability black holes. Route reflectors relax this by allowing designated routers to re-advertise iBGP routes.

Why subtract 2 when calculating usable hosts?+

The all-zeros host address identifies the network/subnet itself; the all-ones host address is the directed broadcast address. Assigning either to an interface violates IP conventions. Always subtract 2 for IPv4 subnets. (Note: modern systems sometimes allow /31 point-to-point links, but university examinations assume the classical rule.)

Viva Voce Question Bank

Q: What is the fundamental difference between routing and forwarding?
Routing is the control-plane process of determining end-to-end paths using algorithms like Dijkstra or Bellman-Ford. Forwarding is the data-plane process of moving an arriving packet from an input port to the correct output port based on a locally stored forwarding table.
Q: Why does Dijkstra's algorithm fail with negative edge weights?
Dijkstra's algorithm greedily finalizes the shortest distance to a node once it is extracted from the priority queue. If negative edges exist, a later path through an unprocessed node could yield a lower cost, violating the assumption that finalized distances are optimal. Bellman-Ford handles negative weights (but not negative cycles).
Q: Explain the count-to-infinity problem with a concrete example.
In a chain A–B–C, if A fails, B sets its cost to A as infinity. But if C advertises a path to A with cost 2 before B can announce the failure, B updates its cost to 3 via C. C then updates to 4 via B. The costs increment until reaching the infinity threshold (e.g., 16 in RIP), causing prolonged routing loops.
Q: Why is OSPF called "Open"?
It is an open standard, publicly specified in RFC 2328 (OSPFv2) and RFC 5340 (OSPFv3), unlike proprietary protocols such as Cisco's EIGRP. Any vendor can implement it without licensing fees.
Q: What would happen if BGP did not use the AS-PATH attribute?
Without AS-PATH, BGP could not detect inter-AS routing loops. A route could circulate indefinitely between autonomous systems. Additionally, policy filters based on traversed ASes would be impossible.
Q: How does traceroute determine the path without knowing the topology?
Traceroute sends packets with incrementally increasing TTL values. Each router decrements TTL; when it reaches zero, the router returns an ICMP Time Exceeded message, revealing its address. The source maps these responses in sequence.
