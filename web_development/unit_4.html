Section 01

XAMPP Server Configuration

Understanding the local development environment that makes PHP possible

Before one can write a single line of PHP and see it execute, there is a prerequisite that textbooks often gloss over with a single paragraph and a screenshot: the server environment. PHP is a server-side scripting language, which means the code does not execute inside the user's browser the way JavaScript does. Instead, the browser sends an HTTP request to a web server, the web server hands the PHP file to the PHP interpreter, the interpreter processes the code (perhaps querying a database along the way), produces plain HTML, and sends that HTML back to the browser. Without a properly configured web server and PHP interpreter installed on your machine, saving a file with a .php extension and double-clicking it will simply open it in a text editor or display raw code in the browser — it will never execute. This is precisely the problem that XAMPP solves for students and developers.

What Does XAMPP Stand For?

The acronym XAMPP is composed of five letters, each representing a core component of the software stack: X stands for "cross-platform" (meaning it works on Windows, Linux, and macOS), A stands for Apache, the world's most widely used web server software; M stands for MariaDB (a community fork of MySQL, the relational database management system); the first P stands for PHP, the server-side scripting language; and the second P stands for Perl, another scripting language that is included for completeness but is rarely used in the typical Indian university curriculum. The beauty of XAMPP is that it bundles all of these complex, independently developed software systems into a single installer with a unified control panel, so that a student can go from zero to a running web server in under ten minutes without needing to understand Apache configuration files, MySQL initialization, or system PATH variables.

Installing and Configuring XAMPP

The installation process on Windows is straightforward: download the installer from the Apache Friends website, run it, and choose the components you need. For most university coursework, you will need Apache, MySQL, PHP, and phpMyAdmin at minimum. The default installation directory is C:\xampp, and it is generally advisable to accept this default because some PHP configurations use absolute paths that can behave unexpectedly when placed in directories with spaces in their names. Once installed, the XAMPP Control Panel provides Start and Stop buttons for each service. When you click "Start" next to Apache, it binds to port 80 (HTTP) by default; when you click "Start" next to MySQL, it binds to port 3306. If another application on your machine — commonly Skype — is already using port 80, Apache will fail to start, and you will see an error in the log. The remedy is either to change Apache's port (by editing httpd.conf and changing the Listen directive to something like 8080) or to close the conflicting application.

Once both Apache and MySQL are running, you can test the installation by opening a browser and navigating to http://localhost. You should see the XAMPP welcome page. PHP files are placed in the htdocs subdirectory of your XAMPP installation (e.g., C:\xampp\htdocs\myproject\), and they are then accessible in the browser at http://localhost/myproject/filename.php. The phpMyAdmin interface, accessible at http://localhost/phpmyadmin, provides a graphical interface for managing MySQL databases without writing SQL commands directly, though understanding the underlying SQL is essential for examinations.

Why XAMPP Matters for Examinations

Exam Note

Questions about XAMPP configuration appear in practical examinations and sometimes in theory papers as short questions. You should be able to explain what each letter stands for, describe the role of Apache and MySQL, explain the concept of localhost, and describe how PHP files are executed on the server before the HTML reaches the client. A common viva question is: "Why can't you just open a PHP file in a browser like an HTML file?" The answer, rooted in everything discussed above, is that PHP requires server-side interpretation — the browser receives only the output, not the source code.

Section 02

Introduction to PHP & Basic Syntax

The language that powers most of the dynamic web — its origins, philosophy, and grammar

What is PHP?

PHP originally stood for "Personal Home Page" when Rasmus Lerdorf created it in 1994 as a set of Common Gateway Interface (CGI) scripts to track visits to his online resume. As the language grew far beyond its humble origins — attracting contributions from Andi Gutmans and Zeev Suraski, who rewrote the parser in 1997 and founded Zend Technologies — the acronym was retrofitted to stand for the recursive phrase "PHP: Hypertext Preprocessor." This etymological detail, while seemingly trivial, is worth knowing because it appears as a fill-in-the-blank or short-answer question with surprising regularity in Indian university examinations. PHP is a server-side, HTML-embedded, general-purpose scripting language. Let us unpack each of those adjectives carefully, because understanding them is the difference between knowing PHP and merely typing PHP.

Server-side means that PHP code is executed on the web server, not in the user's browser. When a user requests a PHP page, the web server (Apache, typically) intercepts the request, passes the file to the PHP interpreter, which processes the code — performing calculations, reading databases, handling file operations, making decisions — and produces a plain HTML document as output. This HTML is what travels back to the browser. The user never sees the PHP source code; they see only its output. This has profound security implications: since the source code remains on the server, it is theoretically invisible to end users, which is why database credentials, API keys, and business logic can safely reside in PHP files (though security best practices require additional precautions beyond this basic separation).

HTML-embedded means that PHP code is interspersed within HTML markup. Unlike languages such as Python or Java, where you typically generate HTML from within a purely programmatic context, PHP allows you to write HTML directly and then drop into "PHP mode" wherever you need dynamic behavior. This makes PHP uniquely accessible to web designers who already know HTML, because the learning curve is not about learning a new paradigm — it is about adding a dynamic layer to something familiar.

Five Reasons Why PHP Is So Popular

  1. Low barrier to entry: A student can write their first dynamic web page within an hour of installing XAMPP. The feedback loop of "edit file, refresh browser, see result" is almost instantaneous.
  2. Ubiquitous hosting support: Almost every affordable web hosting plan supports PHP out of the box. Deploying a PHP application is often as simple as uploading files via FTP.
  3. WordPress and CMS dominance: WordPress alone powers roughly 40% of all websites on the internet, and it is written in PHP. This creates enormous demand for PHP developers and generates a self-reinforcing cycle of community growth.
  4. Framework maturity: Laravel, Symfony, CodeIgniter, and other PHP frameworks provide modern development patterns (MVC, dependency injection, ORM) that make PHP competitive with newer languages.
  5. Continuous evolution: PHP 7 and 8 brought dramatic performance improvements, strict typing options, named arguments, match expressions, union types, and JIT compilation — demonstrating that the language is actively evolving rather than stagnating.

PHP Basic Syntax

Every PHP script begins and ends with specific delimiters. The standard opening tag is <?php and the closing tag is ?>. Everything between these delimiters is interpreted as PHP code; everything outside them is treated as plain HTML and sent directly to the browser. There is also a short open tag <? that can be used if the short_open_tags directive is enabled in php.ini, but this is considered bad practice because it is not portable across all server configurations, and examination answers should always use the full <?php tag.

PHP statements end with a semicolon (;). This is a common source of syntax errors for beginners — forgetting the semicolon at the end of a line will produce an error, and the error message will often point to the next line, which can be confusing. PHP variables always begin with a dollar sign ($), followed by a letter or underscore, and then any combination of letters, numbers, and underscores. Variable names are case-sensitive: $Name and $name are different variables. PHP is a loosely typed language, meaning you do not declare a variable's type explicitly; the type is inferred from the value assigned. Comments can be written as // single-line, # single-line, or /* multi-line */.

<?php
  // This is a PHP script embedded in HTML
  $greeting = "Hello, World!";
  echo $greeting;   // Output: Hello, World!

  $year = 2024;          // Integer
  $price = 99.95;        // Float
  $name = "Amit";        // String
  $isStudent = true;     // Boolean

  echo gettype($year);   // Output: integer
  echo gettype($price);  // Output: double
  echo gettype($name);   // Output: string
?>

PHP Data Types

PHP supports eight primitive data types that every student must know for examinations. String is a sequence of characters enclosed in single quotes ('hello') or double quotes ("hello"). The crucial difference is that double-quoted strings perform variable interpolation — if you write "Hello $name", PHP will replace $name with its value — while single-quoted strings treat everything literally. Integer represents whole numbers without decimal points. Float (also called double) represents numbers with decimal points. Boolean represents true or false. Array stores multiple values in a single variable (covered in detail in Section 5). Object is an instance of a class. NULL represents a variable with no value. Resource is a special type that holds a reference to an external resource, such as a database connection or a file handle.

Memory Anchor

Think of PHP delimiters as a "stage door": actors (PHP code) perform only when they are on stage (between <?php and ?>). Outside the stage door, the audience sees only the backdrop (HTML). The semicolon is the director's clap — it signals "end of scene."

The echo and print Statements

Both echo and print are used to output data to the browser, but they have subtle differences. echo can take multiple comma-separated parameters (echo "Hello", " ", "World";) while print can take only one argument and always returns the integer 1, making it technically a function-like construct. In practice, echo is slightly faster and is used far more frequently. For examinations, it is sufficient to know that both output strings to the browser, echo does not return a value, and print returns 1.

<?php
  $name = "Priya";
  echo "Hello, $name!";        // Double quotes: variable interpolation
  echo 'Hello, $name!';        // Single quotes: literal output
  // Output: Hello, Priya!Hello, $name!

  echo "<br>";                 // HTML tag for new line in browser
  print "Welcome to PHP";      // Returns 1
  echo "\n";                   // Newline in source code (not browser)
?>
Common Confusion

$message vs $$message: A single dollar sign creates a normal variable: $message = "Hello". A double dollar sign creates a variable variable, where the name of the variable is itself stored in another variable. If $message = "greeting" and $$message = "Hello", then echo $greeting will output "Hello". This is because $$message is interpreted as $greeting. While rarely used in production code, this is a classic examination question.

<?php
  $message = "greeting";
  $$message = "Hello, World!";

  echo $message;      // Output: greeting
  echo $$message;     // Output: Hello, World!
  echo $greeting;     // Output: Hello, World!  (same as $$message)
?>

Section 03

Decision Making & Looping

Controlling the flow of execution — conditionals and iteration in PHP

Every program of any meaningful complexity must make decisions and repeat actions. These two capabilities — branching and iteration — form the backbone of computational logic, and PHP implements them using syntax derived from the C programming language tradition. If you have studied C or Java, the structures will feel immediately familiar. If you have not, the concepts are still straightforward once you understand the underlying logic: a conditional evaluates a Boolean expression and executes different code blocks depending on whether the expression is true or false; a loop evaluates a condition and repeatedly executes a block of code as long as the condition remains true. The subtlety, as always, lies in the details — type coercion in comparisons, infinite loops, off-by-one errors, and the appropriate choice of loop construct for a given scenario.

Conditional Statements

The if-elseif-else Construct

The most fundamental conditional is the if statement. It evaluates the expression within parentheses; if the expression evaluates to true (after PHP's type coercion rules), the code block within braces executes. The optional elseif clause allows checking additional conditions when the first one fails, and the optional else clause provides a default path when all preceding conditions are false. One important PHP-specific detail: the string "0", the integer 0, the float 0.0, an empty string "", a NULL value, and an empty array [] all evaluate to false in a Boolean context. This means if ("0") will not execute its body, which surprises many students coming from languages where any non-empty string is truthy.

<?php
  $marks = 72;

  if ($marks >= 90) {
      $grade = "A+";
  } elseif ($marks >= 80) {
      $grade = "A";
  } elseif ($marks >= 70) {
      $grade = "B+";
  } elseif ($marks >= 60) {
      $grade = "B";
  } elseif ($marks >= 50) {
      $grade = "C";
  } else {
      $grade = "F (Fail)";
  }

  echo "Marks: $marks — Grade: $grade";
  // Output: Marks: 72 — Grade: B+
?>

The switch Statement

When you need to compare a single variable against multiple possible values, the switch statement provides cleaner syntax than a long chain of if-elseif blocks. Each case compares the switch expression against a specific value using loose comparison (==, not ===). A critical detail that appears in examinations: every case block must end with break; to prevent "fall-through" — where execution continues into subsequent case blocks even when the value does not match. The default case handles any value not matched by previous cases.

<?php
  $day = "Wednesday";

  switch ($day) {
      case "Monday":
          echo "Start of work week";
          break;
      case "Wednesday":
          echo "Midweek day";
          break;             // Without break, it would fall through to Thursday
      case "Friday":
          echo "Almost weekend";
          break;
      default:
          echo "Regular day";
  }
  // Output: Midweek day
?>

The Ternary Operator and Null Coalescing

PHP supports the ternary operator ? : for inline conditional expressions: $status = ($age >= 18) ? "Adult" : "Minor";. This is syntactic sugar for a simple if-else and is commonly used for assigning values based on a condition in a single line. PHP 7 introduced the null coalescing operator ??, which returns the left operand if it exists and is not NULL, otherwise returns the right operand: $name = $_GET['name'] ?? 'Guest';. This is extremely useful for handling form inputs and is a cleaner alternative to writing isset() checks.

Looping Constructs

for Loop

The for loop is used when the number of iterations is known beforehand. It consists of three expressions separated by semicolons: initialization ($i = 0), condition ($i < 10), and increment ($i++). The loop body executes repeatedly as long as the condition evaluates to true.

<?php
  echo "<table border='1'>";
  for ($row = 1; $row <= 5; $row++) {
      echo "<tr>";
      for ($col = 1; $col <= 5; $col++) {
          echo "<td>" . ($row * $col) . "</td>";
      }
      echo "</tr>";
  }
  echo "</table>";
  // Outputs a 5×5 multiplication table as an HTML table
?>

while and do-while Loops

The while loop evaluates the condition before each iteration, meaning the body may execute zero times if the condition is initially false. The do-while loop evaluates the condition after each iteration, guaranteeing that the body executes at least once. This distinction is important for examinations: if a question asks "What is the difference between while and do-while?", the answer is that do-while guarantees at least one execution.

<?php
  // while — may not execute at all
  $count = 0;
  while ($count > 0) {
      echo "This will never print.";
  }

  // do-while — executes at least once
  $count = 0;
  do {
      echo "This prints once even though count is 0.";
  } while ($count > 0);
?>

foreach Loop

The foreach loop is designed specifically for iterating over arrays. It has two forms: foreach ($array as $value) which gives you each element's value, and foreach ($array as $key => $value) which gives you both the key and the value. This is the idiomatic way to process arrays in PHP, and it should be preferred over for loops with index variables when working with arrays.

<?php
  $fruits = ["Apple", "Banana", "Cherry", "Date"];

  // Simple foreach
  foreach ($fruits as $fruit) {
      echo "$fruit<br>";
  }

  // foreach with key
  $grades = ["Amit" => 85, "Priya" => 92, "Rahul" => 78];
  foreach ($grades as $student => $score) {
      echo "$student scored $score marks.<br>";
  }
?>

break and continue

The break statement immediately terminates the innermost loop (or switch) and execution continues with the statement following the loop. The continue statement skips the remaining code in the current iteration and jumps to the next iteration of the loop. Both accept an optional numeric argument indicating how many levels of nesting to break out of or skip — break 2 exits two levels of nested loops — but this usage is rare and somewhat discouraged for readability reasons.

Section 04

PHP and HTML Integration

Where server-side logic meets client-side presentation

The fundamental power of PHP lies in its ability to generate HTML dynamically. While a static HTML file delivers the same content to every visitor, a PHP script can examine the current time, the user's input, the contents of a database, or any other state, and produce customized HTML accordingly. This interplay between PHP and HTML is not merely a technical capability — it is the architectural foundation of every dynamic website, from a simple contact form to a full-featured e-commerce platform. Understanding how PHP and HTML coexist within a single file, and how data flows between them, is therefore not an optional skill but a core competency.

When the PHP interpreter encounters a <?php tag, it switches into PHP mode and begins executing code. When it encounters a ?> tag, it exits PHP mode and passes everything between the closing tag and the next opening tag directly to the browser as literal text. This mechanism means you can freely interleave PHP and HTML:

<!DOCTYPE html>
<html>
<head>
    <title>PHP and HTML Demo</title>
</head>
<body>
    <h1>Student Grade Report</h1>

    <?php
    $students = [
        ["name" => "Amit",   "marks" => 85],
        ["name" => "Priya",  "marks" => 92],
        ["name" => "Rahul",  "marks" => 67],
        ["name" => "Sneha",  "marks" => 78],
    ];
    ?>

    <table border="1" cellpadding="8" cellspacing="0">
        <tr><th>Name</th><th>Marks</th><th>Grade</th></tr>
        <?php foreach ($students as $student): ?>
        <tr>
            <td><?= $student['name'] ?></td>
            <td><?= $student['marks'] ?></td>
            <td>
                <?php
                $m = $student['marks'];
                if ($m >= 90) echo "A+";
                elseif ($m >= 80) echo "A";
                elseif ($m >= 70) echo "B";
                else echo "C";
                ?>
            </td>
        </tr>
        <?php endforeach; ?>
    </table>
</body>
</html>

Notice the alternative syntax for control structures: foreach (...): ... endforeach; is an alternative to the brace syntax, and it is particularly useful when PHP code is interspersed with HTML because it makes the template-like structure more readable. Also notice the shorthand <?= expr ?> which is equivalent to <?php echo expr; ?> — this was made permanently available in PHP 5.4 and is the recommended way to output values within HTML.

The Alternate Syntax for Templates

When PHP is used heavily within HTML (as in template files), the alternative control structure syntax using colons and end keywords improves readability significantly. Instead of if (condition) {, you write if (condition):, and instead of the closing brace, you write endif;. Similarly: for (...): ... endfor;, while (...): ... endwhile;, foreach (...): ... endforeach;, and switch (...): ... endswitch;.

Memory Anchor

Think of PHP-in-HTML like a bilingual speaker alternating between two languages mid-sentence. The <?php tag is like saying "Switch to French" and ?> is "Switch back to English." The browser only understands English (HTML); it never hears the French (PHP) — it only hears the translation (the output PHP produces).

Section 05

Arrays in PHP

Storing collections of data — indexed, associative, and multidimensional

An array in PHP is an ordered map — a data structure that associates keys with values. This definition, which appears in the official PHP manual, is worth unpacking because it reveals that PHP's array type is more versatile than the "array" concept in languages like C or Java. In those languages, an array is a fixed-size, sequentially indexed collection of elements of the same type. In PHP, an array can use integer indices, string keys, or a mixture of both; it can grow and shrink dynamically; and it can hold values of different types simultaneously. This flexibility makes the PHP array one of the most powerful data structures in the language, but it also means that students must understand three distinct flavors: indexed arrays, associative arrays, and multidimensional arrays.

Fig 5.1 — Three fundamental array types in PHP

Creating Arrays

There are two syntactic ways to create an array in modern PHP. The long form uses the array() construct: $colors = array("Red", "Green", "Blue");. The short form, available since PHP 5.4, uses square brackets: $colors = ["Red", "Green", "Blue"];. Both are functionally identical, and either is acceptable in examinations, though the short form is now considered more idiomatic in contemporary PHP.

<?php
  // ── Indexed Array ──
  $fruits = ["Apple", "Banana", "Cherry", "Date"];
  echo $fruits[0];          // Output: Apple
  echo count($fruits);       // Output: 4
  $fruits[] = "Elderberry"; // Append to end (index 4)

  // ── Associative Array ──
  $student = [
      "name"  => "Amit Kumar",
      "roll"  => 101,
      "marks" => 87.5,
      "grade" => "A"
  ];
  echo $student["name"];    // Output: Amit Kumar

  // ── Multidimensional Array ──
  $class = [
      ["Amit",  85, "CS"],
      ["Priya", 92, "IT"],
      ["Rahul", 78, "ECE"]
  ];
  echo $class[1][0];        // Output: Priya (row 1, column 0)
  echo $class[1][1];        // Output: 92

  // ── Iterating over arrays ──
  foreach ($student as $key => $value) {
      echo ucfirst($key) . ": $value<br>";
  }
?>

Always state which function you are using and why.

Section 06

Functions in PHP

Reusable blocks of logic — built-in and user-defined

Functions are the primary mechanism for organizing code into reusable, testable, and comprehensible units. In PHP, a function is a block of statements that can be called by name, optionally accept input parameters, optionally return a value, and maintain its own local scope. PHP has thousands of built-in functions — over 7,000 in the standard library — covering string manipulation, array operations, mathematical computation, file handling, date and time processing, and much more. Beyond these, programmers can define their own functions using the function keyword, and this ability is what transforms a sequence of scripts into a structured program.

Defining and Calling Functions

<?php
  // ── Basic function ──
  function greet($name) {
      return "Hello, $name! Welcome to PHP.";
  }
  echo greet("Amit");
  // Output: Hello, Amit! Welcome to PHP.

  // ── Default parameter values ──
  function calculateArea($length, $width = 10) {
      return $length * $width;
  }
  echo calculateArea(5, 20);   // Output: 100
  echo calculateArea(5);       // Output: 50 (width defaults to 10)

  // ── Returning multiple values via array ──
  function getStudentInfo() {
      return [
          "name" => "Priya",
          "roll" => 102,
          "marks" => 95
      ];
  }
  $info = getStudentInfo();
  echo $info["name"];         // Output: Priya

  // ── Type declarations (PHP 7+) ──
  function add(int $a, int $b): int {
      return $a + $b;
  }
  echo add(5, 3);              // Output: 8
  // echo add(5, "hello");     // TypeError in strict mode

  // ── Sum of array function (PYQ) ──
  function sumArray(array $numbers): float {
      $total = 0;
      foreach ($numbers as $num) {
          $total += $num;
      }
      return $total;
  }

Variable Scope

PHP has three variable scopes: local, global, and static. A variable declared inside a function is local to that function and cannot be accessed outside it. A variable declared outside all functions is global and cannot be accessed inside a function by default — to use a global variable inside a function, you must explicitly declare it with the global keyword or access it through the $GLOBALS superglobal array. A static variable, declared with the static keyword inside a function, retains its value between function calls — unlike a local variable, which is destroyed when the function returns.

The header() Function

The header() function sends a raw HTTP header to the client. It must be called before any actual output is sent — before any HTML, echo statements, or even blank lines outside PHP tags. Common use cases include redirecting the user (header("Location: login.php");), setting the content type (header("Content-Type: application/json");), and controlling caching. Manipulating text — the bread and butter of server-side programming

Strings are arguably the most frequently manipulated data type in PHP, because virtually all web output is ultimately a string of HTML, and virtually all user input arrives as a string. PHP offers over 100 string functions in its standard library, covering everything from basic operations like finding length and changing case to advanced pattern matching with regular expressions. For university examinations, the emphasis is typically on the core functions: strlen(), strtoupper(), strtolower(), str_replace(), substr(), strpos(), trim(), explode(), implode(), strrev(), ucfirst(), nl2br(), and number_format(). Understanding these functions well — knowing not just what they do, but what they return when the needle is not found, what happens with empty strings, and how they handle multibyte characters — will serve you in both theoretical and practical examinations.

String Concatenation

This is one of the first syntax differences students must internalize: "Hello" . " " . "World" produces "Hello World". Working with Substrings and Search

The substr() function extracts a portion of a string. Its signature is substr(string $string, int $start, ?int $length = null). If $start is negative, counting begins from the end of the string. If $length is omitted, the function returns everything from $start to the end. The strpos() function finds the position of the first occurrence of a substring. A critical gotcha: if the substring is found at position 0 (the very beginning of the string), strpos() returns 0, which evaluates to false in a loose comparison. Therefore, you must always use the strict comparison !== false when checking whether a substring exists, never the loose != false or the implicit Boolean check.

Memory Anchor

The strpos() gotcha: "Finding something at the start is not the same as not finding it at all." Position 0 means "found at the beginning"; false means "not found." These are both "falsy" in loose comparison, which is why === false is mandatory. Think of it like opening a book: the word you seek might be on page 0 (the cover), which is not the same as the word not being in the book.

Form Processing

Collecting user input — the bridge between HTML forms and PHP scripts

The fundamental interaction model of the early web — and still the most common one — involves a user filling out an HTML form, submitting it, and the server processing the submitted data. PHP makes this process exceptionally natural because the form data arrives in superglobal arrays ($_GET, $_POST, $_REQUEST) that are immediately accessible from any part of the script. Understanding form processing requires understanding three interconnected pieces: the HTML form with its attributes, the HTTP methods GET and POST, and the PHP code that receives, validates, and acts upon the data.

The HTML Form

An HTML form is defined with the <form> tag, which has two critical attributes: action, which specifies the URL of the PHP script that will process the form, and method, which specifies the HTTP method used to send the data. The form contains input elements — text fields, passwords, checkboxes, radio buttons, select dropdowns, textareas, and file uploads — each identified by a name attribute. It is this name attribute that becomes the key in the $_POST or $_GET array on the server side.

GET vs POST Methods

  • Bookmarked and shared via URL

  • NOT suitable for large data

Cookies & Sessions

Maintaining state in a stateless protocol — the twin pillars of user tracking

The HTTP protocol is fundamentally stateless: each request from a browser to a server is independent, carrying no memory of previous interactions. This is fine for serving static documents, but it creates a serious problem for dynamic web applications that need to remember who the user is, what they have in their shopping cart, or whether they have already logged in. Cookies and sessions are the two primary mechanisms that PHP provides to solve this problem, and understanding them — their creation, storage, lifecycle, security implications, and differences — is one of the most important topics in this unit. Examinations test this topic heavily, both in theory and in practical coding questions.

Cookies

A cookie is a small piece of data that the server instructs the browser to store locally. When the browser makes subsequent requests to the same server, it automatically includes the cookie in the HTTP headers, allowing the server to recognize the client. In PHP, cookies are set using the setcookie() function, which must be called before any output is sent to the browser (just like header()). The function signature is setcookie(string $name, string $value, int $expire, string $path, string $domain, bool $secure, bool $httponly). Cookies are accessed via the $_COOKIE superglobal array.

Sessions

A session, unlike a cookie, stores data on the server side. When session_start() is called, PHP creates a unique session ID (a long random string) and sends it to the browser as a cookie named PHPSESSID (by default). On subsequent requests, the browser sends this session ID back, and PHP uses it to look up the corresponding session data file on the server. Session variables are stored in the $_SESSION superglobal array. Sessions are generally preferred over cookies for storing sensitive information because the actual data never leaves the server — only the session ID travels back and forth.

Most Commonly Confused Points

Confusion Busters

1. == vs ===: == compares values after type coercion ("5" == 5 is true); === compares both value and type ("5" === 5 is false).

2. echo vs print: echo can take multiple parameters and returns nothing; print takes one parameter and returns 1.

3. include vs require: include gives a warning on failure (script continues); require gives a fatal error (script halts).

4. sort() vs asort(): Both sort by value, but sort() reindexes keys (destroys string keys); asort() preserves key-value associations.

5. $_REQUEST vs $_POST: $_REQUEST contains GET + POST + COOKIE data combined; $_POST contains only POST data. Using $_REQUEST can cause security issues if a GET parameter shadows a POST parameter.

6. $GLOBALS vs $_GLOBALS: The correct superglobal is $GLOBALS. There is no $_GLOBALS.

7. "w" vs "a" in fopen: "w" truncates (erases) the file before writing; "a" appends to the existing content.

8. session_start() placement: Must be called before ANY output — before HTML, before echo, before even a blank line outside PHP tags.

Viva Voce — Quick Conceptual Answers

Click to expand viva preparation

Q: Why is PHP called a server-side language?
A: Because PHP code is executed on the web server by the PHP interpreter. The browser receives only the resulting HTML output, not the PHP source code.

Q: What happens if you forget the semicolon in PHP?
A: PHP will produce a parse error. The error message typically points to the line after the missing semicolon, because PHP realizes the error only when it encounters something unexpected on the next line.

Q: Can PHP run without a web server?
A: Yes, PHP can be executed from the command line using php filename.php. This is called PHP-CLI (Command Line Interface).

Q: What is the difference between unset() and assigning NULL?
A: unset($var) destroys the variable entirely — isset($var) returns false. Assigning $var = NULL sets the value to NULL but the variable still exists — isset($var) returns false in both cases, but array_key_exists() behavior differs.

Q: Why use prepared statements?
A: Prepared statements separate SQL logic from data. The query template is sent to the database first, then the data is bound separately. This prevents SQL injection because user input is never directly concatenated into the SQL string.

Q: What is htmlspecialchars()?
A: It converts special HTML characters to their entity equivalents (e.g., < becomes &lt;). This prevents Cross-Site Scripting (XSS) attacks when displaying user input in HTML.
